# Bug Report Refinement Evaluation Rubric

Each refined bug report is evaluated using eight criteria.

Scoring scale:

- 0 = Criterion not satisfied
- 1 = Partially satisfied
- 2 = Fully satisfied

Maximum total score: 16

| Criterion | Score 0 | Score 1 | Score 2 |
|---|---|---|---|
| Summary Clarity | The issue is unclear or no meaningful summary is provided | The issue is understandable but the summary is weak | The problem is summarized clearly and specifically |
| Steps to Reproduce Completeness | Steps are missing, incomplete, or not actionable | Steps are present but contain some gaps or ambiguity | Steps are complete, ordered, and actionable |
| Expected Behavior Clarity | Expected behavior is missing or unclear | Expected behavior is present but too general | Expected behavior is clearly and specifically stated |
| Actual Behavior Clarity | Actual behavior is missing or unclear | Actual behavior is present but incomplete | Actual behavior is clearly and specifically stated |
| Technical Context Preservation | Important technical context is lost | Most important technical context is preserved | All relevant technical context from the original report is preserved |
| Organization and Readability | The report is poorly organized or difficult to read | Organization is acceptable but could be improved | The report is well structured, readable, and easy to follow |
| Conciseness | Contains clear redundancy or unnecessary content | Some unnecessary content remains | Concise without removing important information |
| Factual Preservation | Changes facts or introduces unsupported information | Minor factual changes or uncertain additions are present | Fully preserves the original facts without inventing new information |

## Overall Score Interpretation

- 0–5: Poor
- 6–10: Moderate
- 11–13: Good
- 14–16: High Quality
